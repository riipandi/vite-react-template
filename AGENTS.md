# AGENTS.md

Starter template for a React 19 + Vite 8 + TypeScript SPA using TanStack Router, TanStack Query/Form/Store, StyleX, and Base UI.
You are helping maintain this template for its author.

## Tech Stack & Tooling

- React 19 + Vite 8 + TypeScript, package manager: pnpm (see `packageManager` in package.json).
- TanStack Router for routing, TanStack Query for server state, TanStack Form, TanStack Store.
- StyleX for all styling (plus `@stylexjs/atoms` for one-off utility styles), Base UI for headless primitives, Lucide Icons for icons, ofetch for HTTP.
- Linting and formatting use Oxc tools (`oxlint`, `oxfmt`), configured in `.oxlintrc.json` / `.oxfmtrc.json`. No ESLint/Prettier.
- Storybook 10 (framework `@storybook/tanstack-react`) with addons: a11y, docs, links, mcp, vitest, performance-panel.

## Build / Test / Lint

Run these with pnpm:

- `pnpm dev` — dev server on port 3000 (strict port; fails if busy).
- `pnpm build` — `tsr generate && tsc -b && vite build`; output to `dist/`.
- `pnpm test` — unit tests (Vitest, project `unit`).
- `pnpm test:storybook` — Storybook interaction tests (project `storybook`, real Chromium via Playwright).
- `pnpm test:coverage` — unit tests with coverage (thresholds in `vitest.config.ts`).
- `pnpm test:ui` — Vitest UI; open the tokened URL printed in the terminal (UI requires token auth).
- `pnpm lint` — `oxlint --fix .`
- `pnpm format` — `oxfmt --write .`
- `pnpm check` — `oxfmt --check` (formatting verification).
- `pnpm typecheck` — `tsc -b --noEmit`.
- `pnpm storybook` — Storybook dev server on port 6006.
- `pnpm knip` — unused exports/files check.

## Architecture

- `app/` is the source root. Import from it with the `#/*` alias (e.g. `#/components/...` → `app/components/...`); relative imports stay within a directory.
  - `app/routes/` — file-based TanStack Router routes (route groups: `(app)`, `(auth)`).
  - `app/components/` — shared components (`base/`, `extra/`, `icons/`, `theme/`).
  - `app/styles/` — StyleX design tokens and styling (`core/`, `element/`, `pages/`).
  - `app/schemas/` — Zod schemas (shared with TanStack Form validation).
  - `app/libraries/` — API client (ofetch), TanStack Stores, and auth guards.
  - `tests/` — unit tests for non-component code (pages under `tests/page/`), shared helpers and setup.
- `app/routes.gen.ts` is generated by `tsr generate` (also runs inside `pnpm build`). Never edit it by hand; implement route files in `app/routes/` and regenerate.

### Component structure

Each component folder in `app/components/<area>/<name>/` follows the same layout:

- `<name>.component.tsx` — the component.
- `<name>.stylex.ts` — StyleX styles (exported as `<name>Styles`).
- `<name>.stories.tsx` — Storybook stories, colocated next to the component (indexed by the `stories` glob in `.storybook/main.ts`). Not in a `storyblock/` subfolder.
- `index.ts` — re-exports the component and its styles.

### Testing rules

- **Do not write separate unit tests for components under `app/components/`.** Component behavior is covered by the interaction tests in each component's Storybook stories (`*.stories.tsx`), run via `pnpm test:storybook` (Vitest project `storybook`, browser mode with Playwright Chromium, a11y checks via `@storybook/addon-a11y`).
- Unit tests (`*.test.tsx` under `tests/`) are only for non-component code: pages (see `tests/page/`), libraries, and utilities.

## Conventions

- Style everything with StyleX. Follow `llms/stylex-authoring.md` — it documents authoring rules and common antipatterns (e.g. don't import non-StyleX values at module scope, don't use `style`/`className` props on StyleX components). Set up details: `llms/stylex-installation.md`.
- StyleX is compiled by `@stylexjs/unplugin` (vite config and `.storybook/main.ts` `viteFinal`) with `useCSSLayers: true`; tokens come from `app/styles/core/*.stylex.ts` (light defaults + `themes.ts` with a single dark `createTheme`; theme class lives on `documentElement`).
- `@stylexjs/atoms` for one-off layout in stories/routes: static styles by property access (`atoms.display.flex`), dynamic values by bracket-string form (`atoms.gap['8px']`) — numeric calls like `atoms.gap(8)` emit invalid unitless CSS.
- Use Zod schemas from `app/schemas/` for form validation (TanStack Form), not inline validation.
- Page-level shared styles (page header, kicker, card grid) live in `app/styles/pages/page.stylex.ts`; reuse them instead of redefining per-page.
- Surface style conventions (keep components in sync):
  - Radius by role: tooltip, kbd, small chips = `radius.small`; buttons, inputs, popups, menus = `radius.medium`; cards, toolbars, menubar, preview-card, empty state = `radius.large`; modals, drawers, sheets, command dialog = `radius.xlarge`; toasts (stacked cards) = `radius.medium`.
  - Title tiers: modal surfaces (dialog, alert-dialog, drawer, sheet) use `fontSize.body1` + `fontWeight.semibold`; inline titled surfaces (alert, popover, item, empty) use `fontSize.body2` + `fontWeight.medium`.
  - Focus rings: form-control inputs draw an inset outline (`outlineOffset: calc(-1 * stroke.border)`); standalone controls draw an outside outline (`outlineOffset: stroke.focus`); slider thumbs and OTP slots draw a `stroke.halo` box-shadow at 50% `foregroundPrimary`. Never leave `outline: 'none'` without a visible `:focus-visible`/state replacement.
  - Disabled controls use `opacity: 0.5` — never a per-component value.
  - Media queries: raw string keys in `stylex.create` conditionals are fine (`'@media (min-width: 660px)'`); `defineConsts` media keys must be **exported** and declared in the same file that uses them (babel limitation). Align boundaries to the token breakpoints (660/900/1280), not raw 640px.
- TypeScript strictness is enforced via `tsc -b`; run `pnpm typecheck` after changes that touch types.

## Common Tasks

- **Add a route**: create a file in `app/routes/` (e.g. `app/routes/about.tsx`), then run `pnpm build` or `npx tsr generate` to refresh `app/routes.gen.ts`. Type-safe links are derived from the generated route tree.
- **Add a component**: create `app/components/<area>/<name>/` with the four-file layout above. Add stories for each meaningful UI state — they are the component's tests. Verify with `pnpm test:storybook`.
- **Change design tokens**: edit `app/styles/core/*.stylex.ts` — consumers pick up the change through StyleX compile-time constants.
- **Run the full pre-commit suite locally**: `pnpm pre-commit` (lefthook: format, lint, typecheck, unit tests on staged files).

## Gotchas

- `app/routes.gen.ts` and `.tanstack/` are generated artifacts — never commit hand-edits to `routes.gen.ts`; regenerate instead.
- `pnpm dev` fails if port 3000 is taken (strictPort). Free the port or change it in `vite.config.ts` before starting.
- `lint` and `format` write fixes in place (`--fix` / `--write`); `pnpm check` only verifies formatting.
- The start/preview scripts serve `dist/` — run `pnpm build` first or you serve stale output.
- Vitest UI (`pnpm test:ui`) requires an authenticated URL: open the `?token=...` URL printed in the terminal; the token changes on every run.
- `.npmrc` sets `min-release-age`: brand-new package versions can be rejected when a command triggers an implicit `pnpm install` (e.g. `pnpm storybook`). Pin an older version or wait out the release-age window.
- Icons: import Lucide icons as named imports with the `Icon` suffix (`import { UploadIcon } from 'lucide-react'`), never `import * as Lucide` — the barrel executes ~1.5k icon modules and the suffix avoids name clashes.
- StyleX gotchas: `defineConsts` works as a media-query key only when declared in the same file as the `create()` call; `stylex.props()` must receive compiled styles (never a plain object or module-level array). If the dev server throws a CSS parse error (`virtual:stylex.css` 404), first check the file edited last for syntax slips (missing comma between entries) and restart Storybook — stale transform state keeps 404-ing after the fix.
- Base UI gotchas: `CardTitle`/`CardDescription` have no `render` prop (use `Text render={<h1/>}` for headings); in a `render` prop, put content inside the render element itself, not the component's children, or oxlint flags an empty anchor/control.
- Layout gotchas: `ButtonGroup` root is `width: fit-content` — full-width joined buttons need `width: '100%'` on the group style and each child Button; `CardHeader` is a `1fr/auto` grid tuned for left-aligned cards — for a centered header override it to a flex column and pin `CardAction` with `position: absolute` (plus `position: relative` on the Card); `FieldSeparator`'s content background must match its surrounding surface (`backgroundElevationBase` when inside a Card), not `backgroundPage`.
